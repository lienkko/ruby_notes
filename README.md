# Трекер заметок

**Название проекта:** «Трекер заметок».

Это веб-приложение для создания, хранения и организации личных заметок. Пользователь сможет добавлять новые записи, просматривать список заметок, открывать отдельную заметку, редактировать и удалять ее. Для удобной навигации заметки можно будет искать по заголовку и фильтровать по категории или тегам.

Целевая аудитория проекта — пользователь, которому нужно быстро фиксировать учебные, рабочие и личные мысли в одном месте.


### Основные экраны

1. **Главная страница / список заметок**
	- отображает заметки пользователя;
	- содержит поиск и фильтры;
	- переход на просмотр заметки;
	- переход на создание новой заметки;
	- переход на редактирование выбранной заметки.

2. **Создание заметки**
	- форма с заголовком, текстом, категорией и тегами;
	- после сохранения переход на страницу созданной заметки или обратно к списку;
	- возможность отменить создание и вернуться к списку.

3. **Просмотр заметки**
	- отображает заголовок, содержимое, дату создания и дату изменения;
	- переход на редактирование;
	- удаление заметки с возвратом к списку;
	- возврат к списку заметок.

4. **Редактирование заметки**
	- форма с текущими данными заметки;
	- после сохранения переход на страницу заметки;
	- возможность отменить изменения и вернуться к просмотру.


### Переходы

```text
Главная / список заметок
├── Новая заметка -> Создание заметки -> Просмотр заметки
├── Выбор заметки -> Просмотр заметки
│   ├── Редактировать -> Редактирование заметки -> Просмотр заметки
│   ├── Удалить -> Главная / список заметок
│   └── Назад -> Главная / список заметок
└── Поиск и фильтры -> Обновленный список заметок
```

##  Стек технологий

### Backend

- **Ruby** — основной язык программирования;
- **Ruby on Rails** — веб-фреймворк для маршрутизации, контроллеров, моделей и работы с базой данных;
- **SQLite** — база данных для учебной версии проекта;
- **Active Record** — работа с таблицей заметок и валидация данных.

### Frontend

- **HTML5** — структура страниц и форм;
- **CSS3** — оформление и адаптивная верстка;
- **ERB** — генерация HTML-шаблонов на стороне сервера;
- **JavaScript** — небольшие интерактивные элементы, например подтверждение удаления и фильтрация.


## Подводные камни

### Данные и датасеты

Внешний датасет не требуется: заметки создаются самим пользователем и хранятся в локальной базе данных. Нужно предусмотреть обязательные поля, ограничения длины и корректную обработку пустых или слишком больших значений.

### Открытые API

Для базовой версии открытые API не нужны. Это уменьшает количество внешних зависимостей и проблем с доступностью сервисов. В дальнейшем можно добавить API, например для получения цитат или автоматического определения категории.

### Сложная логика

- поиск по заголовку и тексту заметки;
- фильтрация по категориям и тегам;
- сортировка по дате создания или изменения;
- валидация формы создания и редактирования;
- подтверждение удаления, чтобы избежать случайной потери данных;
- корректное отображение пустого списка и результата поиска;
- обработка ситуации, когда запрошенная заметка не существует.

### Возможные ограничения

На начальном этапе приложение рассчитано на одного пользователя. Авторизация, совместный доступ, права пользователей и синхронизация между устройствами могут быть добавлены позже.
